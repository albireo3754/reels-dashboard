# 홈 화면 제작 브리핑

2026-10-31 사용자 선택: 기존 모바일 브리핑을 홈 화면에 추가해 앱처럼 사용한다. 네이티브 WebView 앱을 새로 만들지 않고 기존 Sites 인증·조회 계약을 재사용한다.

## 설치

- iPhone/iPad: Safari에서 기존 사이트를 연 뒤 공유 → **홈 화면에 추가**. **웹 앱으로 열기**가 보이면 켠다. 첫 실행에서 로그인은 다시 필요할 수 있다.
- 설치 이벤트를 지원하는 브라우저: 화면의 **앱 설치**를 누른다. 이벤트가 없는 브라우저에는 메뉴에서 추가하는 방법을 안내한다.
- 홈 화면의 아이콘으로 열면 standalone 모드로 표시하며 설치 안내를 숨긴다. 작은 화면에서는 도입 문구를 줄이고 현황을 먼저 보여준다.
- 설치된 앱도 기존 사이트의 허용 사용자만 접근할 수 있다. 사이트 audience나 인증을 변경하지 않는다.

## 연결과 데이터

- 화면 복귀·네트워크 복구 때 다시 조회하고, 보이는 동안 30초마다 확인한다. 중복 요청을 막고 12초 이후 요청 지연을 표시한다.
- Mac 연결 상태, 서버 마지막 동기화 시각과 이 기기에서 확인한 시각을 구분한다.
- 열린 화면에서 연결이 끊기면 마지막 메모리상의 내용을 오래된 정보로 표시한다. 재연결하면 갱신한다.
- 오프라인 상태로 앱을 다시 열면 일반 연결 안내만 표시한다. Cache Storage에는 개인 정보 없는 `offline.html` 하나만 저장한다. 인증 페이지·API 응답·미디어·제작 정보는 캐시하지 않는다.
- 401/403/인증 리다이렉트를 받으면 기존 제작 정보와 열린 상세를 지우고 로그인 확인 링크를 표시한다. 홈 화면 추가는 로그인이나 원본 읽기 권한을 넓히지 않는다.
- 모바일 원본 중계는 계속 비활성이다. 이 변경은 진행 현황·문안·기존 지도 조회 경험에 한정된다.

## 검증

`npm run dev -- --port 5227` 후 `npm run test:pwa`로 로컬 합성 데이터 검사를 실행한다. 테스트는 localhost만 허용하며 합성 Sites 인증 헤더로 로컬 로그인 사용자를 제공한다. production 인증을 우회하는 코드는 추가하지 않았다.

검사: manifest/아이콘/Apple 메타·viewport, iPhone 설치 안내, 설치 이벤트, standalone 안내 숨김, 390px 배치, 오프라인 재열기, 온라인 복구, 401 시 데이터 제거, 캐시 키와 인증 리다이렉트 캐시 거부. 스크린샷을 직접 확인했고 타입 검사와 Sites 빌드가 통과했다.

Chromium 모바일 에뮬레이션과 standalone 감지 시뮬레이션이며 실제 iPhone의 홈 화면 설치·로그인 세션 유지는 자동 검증하지 않았다. 실제 기기에서 설치 후 로그인·앱 닫기/재실행·네트워크 끊김/복구를 한 번 확인해야 한다.

근거: [Apple 홈 화면 웹 앱 안내](https://support.apple.com/guide/iphone/iphea86e5236/ios), [WebKit 홈 화면 웹 앱과 manifest](https://webkit.org/blog/13878/).
