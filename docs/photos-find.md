# 촬영 날짜·길이로 원본 찾기

촬영 보관함에서 날짜를 고르고 **촬영본 빠르게 찾기**를 사용한다. **어제**는 컴퓨터의 현지 날짜 기준 전날을 선택한다. 종류(영상/사진/전체), 영상 최소·최대 길이(초, 경계 포함), 파일명 일부를 조합한다. **약 2분**은 90~150초 프리셋이며 자동 검색하지 않는다.

결과는 촬영 시각순이며 파일명·촬영 시각·길이·해상도를 보여준다. **촬영 그룹 보기**에서 기존 미리보기를 확인하거나, **프로젝트로 추가**로 기존 Photos 원본 복사·편집 프로젝트 생성 경로를 실행한다. 원본을 변경하지 않는다. 날짜나 조건을 바꾸면 이전 결과를 숨기고, 검색 중 실패하면 성공한 일부 결과처럼 표시하지 않는다.

## CLI / MCP

```sh
reels photos-find --date 2026-01-15 --min-duration 90 --max-duration 150
reels photos-find --date 2026-01-15 --filename IMG_1234
reels photos-find --date 2026-01-15 --media-kind photo
```

MCP 이름은 `reels_photos_find`. 기본 종류는 `video`. 길이 조건은 영상에만 사용할 수 있고 `filename`은 대소문자를 구별하지 않는 부분 일치다. `date`는 실제 달력 날짜여야 한다. 상대 날짜의 CLI 해석은 없으므로 호출자가 현지 날짜를 계산한다.

`matches[]`의 `id`, `groupId`, `indexRunId`를 기존 `photos-inspect`·`import-photos-video`에 넘긴다. `scannedCount`는 그 날짜에 조회한 고유 자산 수다. 반환 `groups`는 같은 실행의 장면별 그룹 목록이다.

이 기능은 날짜 색인을 새로 만들고 모든 장면별 그룹의 메타데이터를 읽는다. 현재 색인과 기존 선택용 ID를 대체하므로 readOnly 도구로 표시하지 않는다. Photos 원본은 읽기만 한다. 재색인 뒤에는 이전 결과 ID를 재사용하지 않는다. 원본 다운로드·영상 분석·OCR은 검색에 필요하지 않다. Photos의 기존 권한이 필요하며 제한 권한이면 허용된 자산만 검색된다.

‘집에서’, ‘리뷰’ 같은 내용이나 말소리의 의미 검색은 아니다. 날짜·길이로 찾은 후보를 미리보기로 확인한다. GPS/OCR 검색은 기존 `photos-search`를 쓴다.
