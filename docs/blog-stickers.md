# 기본 스티커 배치

마크업 정본 편집기에서 **스티커**를 열고, 인사·맛있다·추천·마무리 중 필요한 용도를 골라 자리를 잡는다. 사진·문단을 누르면 그 뒤가 삽입 위치로 선택된다. 위치 목록으로 다른 묶음이나 사진 앞뒤로 옮길 수 있고, 선택 메모·삭제·위치 보기도 제공한다. 정본 저장 전 변경은 본문과 같은 저장 상태를 사용한다.

용도 네 가지는 네이버 상품명이나 실제 스티커 목록이 아니다. 아이콘은 용도를 구분하는 표시다. 네이버 기본 목록에서 손 흔들기, 먹고 만족하기, 엄지·끄덕이기, 웃으며 인사하기 같은 표정을 선택하는 계획이며, 실제 캐릭터·팩·표정은 선택 메모로 남길 수 있다. 목록과 사용 권한을 확인하지 않은 상품 ID나 이미지 URL은 포함하지 않는다.

## 배치 기준

- 첫 사진과 방문 이야기를 보여준 뒤 인사. 대표 사진보다 먼저 스티커를 자동 삽입하지 않는다.
- 음식 사진과 맛 설명을 붙여두고 감상이 끝나는 곳에 만족 표정.
- 추천 근거를 쓴 뒤 추천 표정. 스티커로 경험·평가를 대신하지 않는다.
- 마지막 감상 뒤 마무리. 주소·지도·태그는 읽기 쉽게 남긴다.
- 한두 개부터 시작한다. 같은 자리는 하나만 허용하고, 4개 이상이면 줄일지 안내한다. 전체 글이나 매 묶음에 자동 배치하지 않는다.

## 네이버 이관

저장 후 **배치 메모 복사**로 현재 화면의 위치·용도·선택 메모를 가져간다. SmartEditor의 해당 위치에서 도구 막대 → 스티커 → 기본 목록의 원하는 표정을 본문으로 끌어 놓는다. 자리 표시를 실제 스티커로 교체하고 중복·간격을 확인한다. 별도 구매, 네이버 자동 조작, 임시저장, 발행은 이 기능에 포함하지 않는다.

공식 사용 근거: [네이버 블로그 고객센터 — 스티커 첨부 방법](https://help.naver.com/service/5593/contents/15529?lang=ko), 2026-11-03 확인. 도구 막대에서 스티커 패널을 열고 본문으로 끌어 놓는 방식이다. 계정별 기본 팩·이미지 및 실제 네이버 배치는 별도 확인이 필요하다.

## 저장 계약

```text
<Sticker id="s1" preset="yum" note="기본 목록의 만족 표정"/>
```

`preset`은 `hello`, `yum`, `like`, `bye`. 컴포넌트의 순서가 정본 위치다. 편집 API에서는 스티커를 제외한 묶음의 노드 사이 위치(`bundleId`, `before`)를 사용하고, 저장 시 정본 컴포넌트로 변환한다. 숨긴 Title의 인덱스를 보존하며 Title 앞·Tags 뒤는 새 위치로 제공하지 않는다. 문단 내부나 사진 묶음 내부에는 끼우지 않는다.

기존 문장·부분서식·사진을 보존하며 정본 백업과 3-way merge를 그대로 사용한다. 스티커 변경은 구조 변경이므로 화면·배치 검토가 오래된 것으로 표시되고, 문체 검토의 text hash는 바뀌지 않는다. 저장 실패 시 배치와 본문 편집을 화면에 유지한다. 기존 저장 클라이언트가 `stickers` 필드를 생략하면 저장된 배치를 유지한다.

미리보기에도 ‘자리 표시 · 네이버에서 기본 스티커로 교체’라는 표식을 렌더링한다. 실제 네이버 스티커 렌더링과 크기 일치를 주장하지 않는다. 콘텐츠 정본에 스티커를 자동으로 추가하지 않는다.

## 검증 — 2026-11-03

관련 단위 19개, 웹 3개(390/1440px 배치·저장 실패·재열기·기존 서식/사진 배치), 개발 Electron 1개, 타입·FSD·웹/데스크톱 빌드가 통과했다. Electron의 제한된 편집 창은 네이티브 클립보드 쓰기를 사용하며 브라우저 권한을 추가로 열지 않는다. 테스트는 클립보드 쓰기를 가로채 사용자의 실제 클립보드를 보존한다. 개인 원고 수정·실제 네이버 삽입은 수행하지 않았다.

새 패키지 `release/blog-stickers-20261103/mac-arm64/Reels Dashboard.app`에서도 동일한 Electron 검사 1개가 통과했다. 기존 설치 앱 교체·재시작은 수행하지 않았다.

## 워크플로 맥락·화면 검토 — 2026-11-03

문단 텍스트 판정과 별도로, 문안·사진 구성이 확정된 뒤 스티커를 판단한다. 전체 개선 워크플로의 마지막 문안 결정/최종 검토 다음 단계이며 `scope:"stickers"`로 해당 단계만 실행할 수도 있다. 스킬 계약은 콘텐츠 작업공간의 `rosy-blog-review-loop` 스킬 `references/sticker-review.md`에 있다.

CLI는 `node --import tsx scripts/blog-sticker-review.ts prepare <projectId> <새 패킷 절대 경로>` → 독립 context/visual 출력 → `finish <패킷>` 순서다. 현재 정본·서식을 고정하고 스티커 묶음과 이웃 경계를 360/390/430px로 캡처한다. 모델 실행·사용자 원고 수정은 prepare에 포함하지 않는다. context는 모든 묶음의 필요/생략, visual은 기존 스티커 전체의 제공된 화면을 판단한다.

finish는 지문·증거 바이트·출력 누락을 검증한다. 텍스트 검토 결과와 실제 네이버 이미지 검증은 별개다. 승인된 배치 개선은 `apply <패킷> <plan.json>`으로 기존 저장 가드를 거쳐 스티커만 반영하고 새 패킷에서 재검토한다. 새로운 준비/검증/적용 검사3개와 기존 스티커 검사3개, 타입/FSD 통과. 기능은 CLI/워크플로 추가이며 설치 앱 교체가 필요하지 않다.
