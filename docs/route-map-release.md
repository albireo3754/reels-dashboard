# 촬영 지도 통합 적용 — 2026-10-31

콘텐츠에 등록한 지도 JSON을 데스크톱과 기존 브리핑 사이트에서 함께 확인할 수 있게 했어요. [앱 사용법](route-map.md), [동기화 계약](route-map-sync.md)을 정본으로 삼아요. 지도 생성·원본 자동 확보와 영상 업로드는 이번 기능에 포함하지 않아요.

## 적용 결과

- 앱 번들: `release/route-map/mac-arm64/Reels Dashboard.app`. 기존 번들을 덮어쓰지 않고 별도 패키징했어요. 편집 dirty=false·진행 중 렌더 없음 확인 후 새 앱을 실행했어요.
- 실행 앱에서 실제 콘텐츠의 지도·도로·경로·시간별 핀·원본 연결 버튼을 확인했어요. 원본이 없는 촬영분은 명시적으로 미연결 상태예요.
- Sites 기존 프로젝트의 v4 배포 성공. 소스 commit `d914b408c69aa3eb2f5ede9edf6239535ef9d92b`, 기존 사이트 주소와 허용 사용자 유지. 공개 접근으로 바꾸지 않았어요.
- 배포 후 기존 bridge LaunchAgent를 재시작했어요. 서버 snapshot 갱신과 지도 준비 상태·미디어 종류 필터·위치 불확실 표시를 확인했어요. 실제 snapshot 시각과 개인 촬영 집계는 콘텐츠 작업공간의 비공개 검증 기록에만 보관해요.
- 서버 지도 DTO에 로컬 파일 경로·source·thumbnail 필드가 없고 `mediaEnabled=false`임을 확인했어요. 원본 재생 서비스의 기존 상태는 유지했어요.
- 실제 배포 사이트에 기존 계정으로 로그인해 시간별 핀 선택과 영상 필터를 확인하고,390px 화면에서 지도·조절기·목록이 가로 잘림 없이 표시됨을 확인했어요. 로컬 preview의 mock sign-in403과 일시적인 browser timeout은 production 확인 완료와 구분해요.

## 검증

- 앱: 타입·FSD·빌드, 앱 단위4개, 관련 SDK·기존 문안/객체 회귀 포함10개, 웹2개, 개발Electron1개, 패키징Electron1개 통과.
- 패키징 테스트는 실제 합성 영상 재생, 선택 변경 시 해제, 재시작·등록문서 갱신·누락 원본을 검사했어요. `test-results/route-map-packaged`에 결과가 있어요.
- 사이트: 타입·계약·용량제한 검사, 로컬D1 저장/갱신/삭제·민감필드 제거·잘못된좌표 거부·기존미디어비활성, 빌드·diff 검사 통과. 신규nullable 컬럼 migration이 배포에 포함됐고 실제 서버 재조회도 성공했어요.
- 독립 검토에서 발견한 큰지도 전체동기화 실패, D1행한도, 불확실핀 지도범위 문제를 수정했어요. bridge 지도1MiB·전체3.5MiB, 서버행1.9MB 상한으로 범위를 제한해요.
- 실제 원본 연결은 일부 촬영분에서 확인했어요. 나머지 촬영분은 파일명·촬영정보·위치가 보이며 원본을 확보한 상태로 표현하지 않아요. 사이트의 원본 재생은 아직 비활성이에요.

## 동기화 의미

앱은 열린 지도 문서를30초마다 확인하고, bridge는60초마다 수집하며, 사이트는30초마다 서버를 다시 읽어요. 같은 정본을 함께 반영하지만 두화면을 원자적으로 동시에 갱신하는 기능은 아니에요. Mac·앱·bridge가 꺼지면 사이트는 마지막 저장본을 보여줘요.
