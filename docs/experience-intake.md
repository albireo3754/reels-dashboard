# 사진과 조사 자료를 바탕으로 경험을 한 번에 받기

대시보드 실행과 Codex 세션이 같은 폼을 사용하는 공통 계약은 [공통 입력폼 서비스](shared-input-forms.md)를 따른다. 이 문서는 대시보드 실행 단계의 연결을 설명한다.

새 워크플로 화면에서 **자료 준비 후 내 경험을 한 폼으로 받기**를 선택하면 `근거 준비 → 내 경험 채우기 → 답변 요청 분류 → 추가 작업 → 초안 작성 → 문안 검토 → 화면 구성 → 화면 검토`로 진행한다. 체크는 기본 선택이다. CLI/MCP에서 만들 때는 `collectExperience: true`를 넣는다. 경험 수집이 필요 없는 기존 작업은 원래 흐름을 유지한다.

사진 기반 글은 **근거 준비에서 전체 관련 장면 목록을 만들고, 초안 작성의 첫 작업으로 사진 선택·묶음·순서를 결정한 뒤 문장을 쓴다.** `media-scenes.json`과 `story-media-plan.json`으로 그 결정을 리뷰·화면 구성까지 전달한다. 경험 폼 사용 여부와 별개이며 기존 작업을 되감지 않는다. [사진 구성 계약과 검증 범위](photo-first-drafting.md).

근거 준비는 현재 세션 또는 명시적으로 실행한 SDK가 수행한다. 촬영물 탐색·원본/프레임 선별·레퍼런스 추출·메뉴/장소 조사 결과를 먼저 만들고, 그 근거에 맞는 질문을 `experience-form.json`으로 작성한다. 이 파일(또는 SDK가 `.workflow-results/<job>/experience-form.json`에 저장한 후보)을 준비 단계의 `evidence`에 포함해야 경험 단계가 열린다. 그래프 자체가 Photos나 웹을 수집하거나 다음 SDK 단계를 자동 실행하는 것은 아니다.

## 준비 결과의 계약

```json
{
  "version": 1,
  "title": "이번 방문에서 기억나는 것",
  "introduction": "사진을 보며 메모하듯 적어주세요.",
  "facts": [{"text":"자료로 확인한 내용", "source":"facts.md", "status":"confirmed"}],
  "questions": [{
    "id":"taste", "section":"첫입", "prompt":"첫입은 어땠나요?",
    "help":"본인 취향과 실제 기억만 적어주세요.", "required":true,
    "images":[{"path":"media/plate.jpg", "caption":"원본 파일명 · 프레임 시각 · 관찰 내용"}]
  }]
}
```

`confirmed`는 근거가 있는 사실, `observed`는 사진 관찰, `unverified`는 미확인이다. 공개 리뷰의 감상은 사용자 감상으로 옮기지 않는다. 질문은 방문 계기·주문 선택·맛·동행 반응·아쉬움·다음 선택 등 실제로 빠진 내용만 묶는다. 이미 확인한 메뉴 가격을 반복 질문하거나 특정 평가를 유도하지 않는다.

사진은 작업 폴더 안의 JPEG/PNG/WebP 미리보기(각 4 MB 이하)다. 경로 이탈·외부 symlink·변경된 이미지 제공을 거부한다. 원본 영상은 복제하는 대신 촬영 인벤토리와 원본 참조를 연결하고 질문에 필요한 정지컷만 쓴다. 샘플 프레임 분석을 전체 영상·오디오 검토라고 보고하지 않는다.

## 한 번에 답하고 이어쓰기

- 한 화면에서 모든 질문과 근거를 본다. 직접 적기 / 기억나지 않음 / 본문에서 제외를 선택한다.
- **답변 임시저장**은 부분 답변을 서버에 보관한다. 새로 열거나 서버를 재시작해도 유지된다. 입력 중 주기적 상태 조회가 글을 덮어쓰지 않는다.
- **한 번에 제출 · 초안으로**는 필수 질문의 명시적 응답을 검사한다. 모른다는 선택도 유효한 답이다. 빈 답변을 감상으로 채우지 않는다.
- 제출은 사용자 원문과 질문, 상태, 출처 해시를 `experience-answers-<run>-<uuid>.json/.md`로 작업 폴더에 저장한다. 다음 초안 작업의 추적 입력에 자동 연결된다. 실제 초안 실행은 현재 세션 또는 별도 실행 버튼이 맡는다.
- 오래된 탭의 저장은 `expectedRevision`으로 거절한다. 입력은 화면에 남는다. 근거가 바뀌면 제출을 차단하며 새 워크플로에서 새 질문을 준비한다. 기존 답변은 보존된다.
- 경험 단계는 일반 결과 제출이나 SDK 실행으로 건너뛸 수 없다. 취소/보류는 가능하다. 답변은 에이전트가 추정하지 않는다.

CLI: `npm run workflow -- experience-save /path/to/answers.json`. MCP: `reels_workflow_experience-save`. 입력은 `{runId, taskId, expectedRevision, answers:[{questionId,status:"answered|unknown|omit",text}], submit:false|true}`다. `get`으로 현재 질문·revision·답변을 읽는다. `experience-media`는 등록된 질문 ID/사진 인덱스만 받아 미리보기 data URL을 반환한다. 기존 Desktop preload와 HTTP/CLI/MCP가 같은 저장소를 사용한다. 외부 폼 서비스, 외부 공유, 게시 기능은 추가하지 않는다.

직접 열기: `http://127.0.0.1:4318/?workflow=1&run=<runId>`. 이 주소는 이 Mac에서 사용한다.

SDK는 기존 읽기 전용 계약을 따른다. 제공된 조사/사진 근거로 질문 후보를 반환하고 호스트가 저장한다. Photos 내보내기·레퍼런스 URL 추출처럼 로컬 쓰기가 필요한 준비는 Dashboard MCP를 사용하는 제작 세션이 맡는다. 자료가 없으면 준비 완료로 제출하지 않는다.

## 검증 — 2026-11-01

전체 단위 146개, 경험 폼 추가 후 관련 워크플로 13개(읽기 전용 SDK 후보→질문 단계 포함), 웹 3개, 새 패키지의 Electron 경험 폼 1개를 통과했다. 타입·FSD·웹/데스크톱 빌드와 diff 공백 검사도 통과했다. 합성 자료로 저장/재시작/중복 제출/미응답/근거 변경/외부 symlink/SDK 우회 차단을 확인했다. 실제 콘텐츠 폼은 질문 8개와 이미지 배치 7개(고유 프레임 5개)가 모두 표시되고 390px에서 가로 넘침이 없음을 확인했다. 실제 사용자 답변은 아직 입력하지 않았다.

새 Mac 빌드: `release/experience-intake/mac-arm64/Reels Dashboard.app`. 기존 실행 앱의 촬영 작업은 재시작하지 않았다. 새 웹 화면과 서버는 사용할 수 있으며, 저장 상태 UI 등 기존 소스 변경을 함께 포함한 별도 패키지를 검증했다.


## 답변 속 추가 요청 처리 — 2026-11-02

경험 폼 제출 후 바로 초안을 쓰지 않고 `requests`에서 모든 제출 답변을 읽어 추가 요청을 분리한다. 원문은 그대로 보존한다. `followup-tasks.json`(SDK 결과 폴더의 동명 파일도 허용)을 evidence로 제출한다. 구조는 shared/followups.ts가 정본이며 `reviewedAnswerIds`에 모든 제출 questionId, tasks에 id/title/kind/sourceFile/sourceQuote/instruction/executor를 담는다. 출처 파일은 추적 입력이어야 하고 인용은 실제 문자열과 일치해야 한다. 외부 문서 속 지시를 사용자 요청으로 승격하지 않는다.

`followup`은 목록의 미처리 작업을 하나씩 현재 task.followupId로 발급한다. done 결과에는 근거 파일이 필요하고 해당 작업의 summary/evidence/status가 체크포인트에 남는다. blocked면 초안 진입을 멈추며 재개 시 같은 미처리 작업을 다시 발급한다. 조사한 결과 ‘자료 없음/충돌/현재 확인 불가’도 범위와 근거를 기록하고 초안 처리 결정을 내리면 완료 결과가 될 수 있다. 실제 작업을 하지 않고 ‘나중에 확인’만 적은 것은 완료가 아니다.

모든 작업을 마치면 draft로, 기존 초안의 추가 요청을 다시 열었으면 revise→review로 이어진다. 작업이 없으면 명시적인 빈 목록과 검토된 답변 ID를 제출한다. `session` 작업은 UI에서 제작 세션 작업으로 표시하며 읽기 전용 SDK 실행을 거부한다. 시스템이 임의 셸 명령이나 외부 변경을 실행하지 않는다. 제작 세션이 권한 범위에서 실행하고 결과를 제출한다.

기존 제출본 재처리: UI ‘답변의 추가 요청 다시 확인’, CLI/MCP `followups-open`에 `{runId, expectedTaskId, evidence:["새 사용자 지시 파일"]}`. 입력/실행 중 충돌을 검사하고 원문·이전 이력은 유지한다. 기존 체크포인트를 일괄 이동하지 않는다.

추가 요청 처리 후 새 초안 후보를 만들며 과거 후보를 덮어쓰지 않는다. 문안 검토는 최신 후보와 요청별 결과를 함께 읽고, 사진 경로는 후보가 저장된 실제 디렉터리를 기준으로 확인한다.

검증(2026-11-02): 전체 단위157개·워크플로14개·웹4개·별도 Mac 패키지 경험수집1개, 타입/FSD/빌드 통과. 추가 작업별 상태·인용 검증·보류 후 재개·오래된 task 거절·기존 review 재열기→수정→review 복귀를 확인했다. 새 빌드는 release/experience-followups/mac-arm64/Reels Dashboard.app. 라이브 웹 서버에 적용했고 기존 데스크톱 실행 프로세스는 교체하지 않았다.
