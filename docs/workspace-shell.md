# 창 구성과 터미널

2026-10-31. Workdesk의 상단 이동 도구와 하단 터미널 구조를 참고해 Reels Dashboard의 창 구성을 정리했다.

- macOS는 기본 타이틀바를 숨기고 상단 52px 도구 영역에 창 제어 버튼 공간을 확보한다. 빈 영역은 창 이동에 사용하고 버튼은 드래그 영역에서 제외한다. 기본 창은 1600×1000, 최소 크기는 기존 760×600이다.
- 큰 브랜드·소개 타이틀·중복 경로 표시를 제거하고, 작업 영역의 최대 폭 제한을 없앴다. 화면 제목은 스크린리더용으로 유지한다.
- 좌측 상단의 뒤로/앞으로와 히스토리는 현재 실행 중 방문한 화면을 최대 30개까지 관리한다. 과거 화면에서 새 화면을 열면 앞으로 이동할 이력을 교체한다. 앱 재실행 후 이력을 복원하지 않는다.
- 검색 버튼이나 `⌘K` / `Ctrl+K`로 메뉴, 콘텐츠 제목과 다음 할 일을 찾는다. 화면의 진행 필터와 무관하게 로드된 콘텐츠를 검색한다. 로컬 결과는 콘텐츠 기록을 열고, 공유 웹 결과는 읽기 전용이다. 닫기·Escape·바깥 클릭을 지원한다. 편집 중인 콘텐츠 기록 위에서는 검색 단축키를 실행하지 않는다.
- 설정은 우측 상단에 둔다. 콘텐츠 메뉴에서는 설정·개발 항목을 제거했다.
- 2026-11-12 툴바 구성: 상단 툴바(`banner` '작업공간 도구')는 본문과 같은 배경에 아래 hairline 하나다. 왼쪽은 작은 회색 `DEV` 글자, 뒤로·앞으로·히스토리 아이콘 버튼, 검색(아이콘 + "검색" + `⌘K`)이다. 오른쪽은 화면 검사·터미널·설정 아이콘 버튼이다. 아이콘 버튼은 글자 없이 툴팁과 기존 aria-label('히스토리', '화면 검사', '터미널', '설정')을 유지하고, 열린 상태는 옅은 선택 배경으로 표시한다.
- 개발모드에서 우측 상단 **터미널** 아이콘으로 기존 PTY 패널을 열고 접는다. 일반 터미널·Codex·미리보기·검증 기능과 세션별 탭은 유지한다. 터미널을 접거나 숨겨도 편집기와 세션을 유지한다. 터미널의 `Ctrl+K` 입력은 셸에 전달한다.

터미널은 `REELS_DEV_MODE=1` 실행이나 **설정 → 터미널 사용** 토글(다음 실행부터 적용)로만 활성화한다. 일반 앱과 공유 웹에 셸 실행 권한을 추가하지 않는다. 세션 시작·종료와 `⌘N/T/W/1–9`는 [개발 작업공간 문서](development-workspace.md)를 따른다.

## 단축키 — 2026-11-04

Workdesk #4·#9·#18·#61·#65의 중앙 keymap 구조를 적용했다. 모든 키는 `src/shared/keymap.ts` 한 곳에서 정의하고 물리 키(`e.code`)로 판정한다. 규칙은 [구조 문서의 Shortcuts](architecture.md#shortcuts)를 따른다.

| 키 | 동작 | 범위 |
| --- | --- | --- |
| `⌘K` / `Ctrl+K` | 검색 열기·닫기 | 모든 모드. 편집 중인 콘텐츠 기록 위와 터미널의 `Ctrl+K`에서는 실행하지 않는다 |
| `⌘[` / `⌘]` | 상단 뒤로/앞으로 이력 이동 | 모든 모드. 이력 끝에서는 아무것도 하지 않는다 |
| 마우스 뒤로/앞으로 버튼 (`MouseEvent.button` 3/4) | `⌘[` / `⌘]`과 같은 이동 | 모든 모드. 이동할 이력이 있을 때만 기본 동작을 막는다 |
| ⌘ 누르고 있기 | 지금 실행 가능한 단축키를 해당 버튼 위에 표시 | ⌘를 떼거나 창이 포커스를 잃으면 사라진다 |
| `⇧⌘C`, `Esc` | 화면 검사 시작, 검사 끝내기 | 개발모드. [개발 작업공간 문서](development-workspace.md#작업공간-탭과-단축키) 참고 |

- 뒤로/앞으로 버튼의 비활성 상태, 단축키 실행 여부, ⌘ 힌트 표시는 같은 `canBack` / `canForward` 규칙을 쓴다. 검색·이력 창이 열려 있어도 이동 단축키는 동작한다.
- 2026-11-04 변경: `⌘K`도 물리 K 키로 판정하므로 다른 자판 배열에서도 같은 키로 동작한다. 수정키는 정확히 일치해야 하므로 `⇧⌘K`, `⌃⌘K` 등으로는 더 이상 검색이 열리지 않는다.
- 알려진 제한: 미리보기 iframe 등 cross-origin 화면에 키보드 포커스가 있으면 `⌘K`·`⌘[`/`⌘]`·`Esc`(검사 끝내기)·⌘ 힌트가 동작하지 않고, 마우스가 그 위에 있으면 마우스 뒤로/앞으로 버튼이 동작하지 않는다. 해당 이벤트가 그 frame 안에 머물고 이 액션들에는 호스트 경로가 없기 때문이다. 상위 화면을 클릭한 뒤 사용한다. 개발모드의 `⌘N/T/W/1–9`·`⇧⌘C`는 main이 받으므로 이 제한이 없다.

## 검증

다른 진행 중 기능의 미커밋 변경을 보존하고, 이번 변경만 기존 main에 적용한 별도 소스를 검증했다.

- 통합 작업 소스: 타입/FSD 검사, 단위76개, 웹·desktop 빌드 통과. 전체 웹75개 중72개가 먼저 통과했고, 닫힌 검색창의 중복 DOM을 수정한 뒤 공유 웹·새 화면 검사10개를 다시 통과했다.
- main 후보 소스: 타입/FSD, 단위30개, 웹·desktop 빌드, 웹59개·Electron13개 통과. 설치된 CLI의 선택적 초기 화면 검사는 건너뛰었으며 모델 작업은 제출하지 않았다.
- Electron에서는 실제 PTY 입력·임시 소스 수정·세션 유지/종료·미리보기 서버 정리·상단 도구 배치를 검사했다. 기본 background QA로 실행해 기존 앱의 포커스를 건드리지 않았다.
- 1600px·760px·390px 웹 화면과 Electron 화면을 캡처해 배치·가로 넘침을 확인했다. native 드래그/no-drag CSS와 창 제어 버튼 여백도 검사했다. 실제 창을 마우스로 끄는 수동 검증은 수행하지 않았다.
- 공개 소스 staged 검사 통과. 개인 데이터·미디어·다른 미커밋 기능을 포함하지 않았다.

실행 중인 설치 앱 교체와 원격 push는 이 변경에 포함하지 않는다. Electron main/preload 변경은 소스 빌드 후 새 실행에서 적용된다.
