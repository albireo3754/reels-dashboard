# 창 구성과 터미널

2026-10-31. Workdesk의 상단 이동 도구와 하단 터미널 구조를 참고해 Reels Dashboard의 창 구성을 정리했다.

- macOS는 기본 타이틀바를 숨기고 상단 52px 도구 영역에 창 제어 버튼 공간을 확보한다. 빈 영역은 창 이동에 사용하고 버튼은 드래그 영역에서 제외한다. 기본 창은 1600×1000, 최소 크기는 기존 760×600이다.
- 큰 브랜드·소개 타이틀·중복 경로 표시를 제거하고, 작업 영역의 최대 폭 제한을 없앴다. 화면 제목은 스크린리더용으로 유지한다.
- 좌측 상단의 뒤로/앞으로와 히스토리는 현재 실행 중 방문한 화면을 최대 30개까지 관리한다. 과거 화면에서 새 화면을 열면 앞으로 이동할 이력을 교체한다. 앱 재실행 후 이력을 복원하지 않는다.
- 검색 버튼이나 `⌘K` / `Ctrl+K`로 메뉴, 콘텐츠 제목과 다음 할 일을 찾는다. 화면의 진행 필터와 무관하게 로드된 콘텐츠를 검색한다. 로컬 결과는 콘텐츠 기록을 열고, 공유 웹 결과는 읽기 전용이다. 닫기·Escape·바깥 클릭을 지원한다. 편집 중인 콘텐츠 기록 위에서는 검색 단축키를 실행하지 않는다.
- 설정은 우측 상단에 둔다. 콘텐츠 메뉴에서는 설정·개발 항목을 제거했다.
- 개발모드에서 우측 상단 **터미널**로 기존 PTY 패널을 열고 접는다. 일반 터미널·Codex·미리보기·검증 기능과 세션별 탭은 유지한다. 터미널을 접거나 숨겨도 편집기와 세션을 유지한다. 터미널의 `Ctrl+K` 입력은 셸에 전달한다.

터미널은 기존처럼 `REELS_DEV_MODE=1` 실행에서만 활성화한다. 일반 앱과 공유 웹에 셸 실행 권한을 추가하지 않는다. 세션 시작·종료와 `⌘N/T/W/1–9`는 [개발 작업공간 문서](development-workspace.md)를 따른다.

## 검증

다른 진행 중 기능의 미커밋 변경을 보존하고, 이번 변경만 기존 main에 적용한 별도 소스를 검증했다.

- 통합 작업 소스: 타입/FSD 검사, 단위76개, 웹·desktop 빌드 통과. 전체 웹75개 중72개가 먼저 통과했고, 닫힌 검색창의 중복 DOM을 수정한 뒤 공유 웹·새 화면 검사10개를 다시 통과했다.
- main 후보 소스: 타입/FSD, 단위30개, 웹·desktop 빌드, 웹59개·Electron13개 통과. 설치된 CLI의 선택적 초기 화면 검사는 건너뛰었으며 모델 작업은 제출하지 않았다.
- Electron에서는 실제 PTY 입력·임시 소스 수정·세션 유지/종료·미리보기 서버 정리·상단 도구 배치를 검사했다. 기본 background QA로 실행해 기존 앱의 포커스를 건드리지 않았다.
- 1600px·760px·390px 웹 화면과 Electron 화면을 캡처해 배치·가로 넘침을 확인했다. native 드래그/no-drag CSS와 창 제어 버튼 여백도 검사했다. 실제 창을 마우스로 끄는 수동 검증은 수행하지 않았다.
- 공개 소스 staged 검사 통과. 개인 데이터·미디어·다른 미커밋 기능을 포함하지 않았다.

실행 중인 설치 앱 교체와 원격 push는 이 변경에 포함하지 않는다. Electron main/preload 변경은 소스 빌드 후 새 실행에서 적용된다.
